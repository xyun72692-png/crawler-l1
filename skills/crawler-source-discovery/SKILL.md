# 源发现与判定（没有网址时怎么找、怎么判值不值得接）

> 对应《爬虫能力报告-完整版》**第十八章**（2026-11-14 重写版）。
> 本技能只负责「找源 + 判形态 + 判平台/皮肤 + 排除」，**不写解析器**（那是 `crawler-site-onboarding` 的事）。

## 一、什么时候用

```
输入：一个目标（"要浙江食品检测岗""要法规全文""要某商品历史价格"）
输出：候选源清单 + 每个源的评分 + 建议抓法 + 可执行的下一步命令
不适用：已知具体站点，直接写适配器 → 用 crawler-site-onboarding
```

## 二、四维评分（不是固定顺序）

| 维度 | 问什么 | 低分样子 |
|---|---|---|
| 适配度 | 这条数据直接回答问题吗 | 只是相关，字段不对 |
| 时效性 | 更新频率够用吗 | 季度更 vs 要日更 |
| 可得性 | 公开吗？SSR/接口？要登录/反爬？ | 付费账号 / 强 WAF |
| 权威性 | 一手还是二手 | 自媒体转述 |

**排序 = 适配 × 时效 × 可得；权威性只作质量标签**。
（政府公告最权威，但求职适配度低 → 排最后。**权威 ≠ 该先抓**。）

## 二·补、**第 0 步：判型（2026-11-15 新增，决定要不要跑六步）**

> 六步发现是「多源任务」的搜索策略，**不是所有任务都要跑完**。

| 型 | 判据 | 需要几个源 | 停止条件 | 典型 |
|---|---|---|---|---|
| **A 单点权威** | 数据只有一个机构在产生 | 1~2 | 找到就停，**不进 ②~⑤** | 天气、国家法规、汇率 |
| **B 多源长尾** | 无数主体各自发布 | 10~50+ | 跑六步，按覆盖度停 | 招聘、租房、招投标 |
| **C 账号在环** | 数据在平台内，用户有账号 | 1（账号） | **先问账号，再谈发现** | 拼多多价格、知乎、微博 |
| **D 开放 API** | 已有现成接口 | 1 | 直接调，不抓页面 | 天气 API、开放数据 |

```
判型三问：
  ① 谁产生这条数据？   一个机构 -> A/D ；无数主体 -> B
  ② 手上有账号吗？     有，且数据在平台里 -> C（立刻停下问用户）
  ③ 有现成接口吗？     有 -> D（连抓都不用）
```

**判型已进代码（2026-11-15，`discover.py --mode` + `--goal`，当前状态）**：

```bash
# 不给 --mode = 0 请求，先把判型三问打出来问你（rc=2，不默认跑 wide）
python tools/discover.py --region 浙江

# A / D 型：只查官方名录 + 直接给 URL，不跑检索/页脚/域名/枚举
python tools/discover.py --region 浙江 --mode single --goal jobs --seed SEED_URL

# B 型：六步全跑
python tools/discover.py --region 浙江 --mode wide --goal jobs --industry 食品

# C 型：零请求，直接打印"要账号"三问
python tools/discover.py --mode account --goal price
```

硬约束（都在代码里，不是靠人记）：

```
--mode 必填       不给 → 0 请求 + 判型三问 + rc=2
--goal 必填       只影响 --print-queries 出哪一类模板（jobs/regulation/price/weather）
                  不给 goal 就 --print-queries → rc=2，不许把 14 条全吐
名录按 goal 过滤  天气任务不会看到招聘站（gov_platforms.json 的 kind 字段）
single 的冲突     single + --search-result/--from-enum → rc=2 拒绝
检索结果校验      解析出 0 条 → rc=2；嵌套 JSON 递归取 URL（不许静默丢）
```

验收标准：single 的输出里不该出现"第 2~5 步"的日志。

**硬规矩**：

```
A / D 型：停在第 ① 步（官方名录 / 直接接口），不许往下跑 ②~⑤
C 型   ：第 0 动作是问用户"有没有账号/能不能登录"，不许先去找聚合站
B 型   ：才跑满六步
```

**反面教材（2026-11-15 用户指出）**：

```
天气   跑六步去搜"XX天气网"、枚举域名    -> 纯浪费，中央气象台/API 一个就够
法规   去找北大法宝、聚合站              -> 一手公报才是答案，1~3 个源
价格   去搜比价网、行业协会              -> 用户手上就有拼多多账号，1 个源搞定
```

## 三、五个来源层（顺序随领域翻转）

```
① 一手发布者   ② 行业垂直   ③ 通用平台/城市站/电商   ④ 聚合索引   ⑤ 二手转述（只作线索）
```

| 领域 | 定稿顺序 |
|---|---|
| 招聘 | 企业（垂直站+本地龙头）→ 城市网 → 政府 |
| 法规 | 一手 → 聚合 → 垂直（付费） |
| 商品价格 | 行情→交易所；零售→垂直/比价 API |
| 天气 | API → 一手 → 聚合 |

**没有万能顺序，只有万能尺子。**

## 四、六条技术路径（**检索优先**，2026-11-14 改版）

> ⚠ **只有 B 型（多源长尾）才跑满六条。** A / D 型停在第 ① 步，C 型直接转账号模式。
> 判型见 §二·补；判错型，后面每一步都是白干。

> 旧版写的是「四条路径、成本递增、顺序不能反」。**那条原则已作废**——
> 因为它的前提是"不许联网"。检索是免费的、几乎零成本、召回最高 —— **但只在需要的时候跑**。
> 准确说法是：**没有候选源、或不知道一手源时，才先检索**。已经知道官方站/API 就别检索（A/D 型）。

| 路径 | 成本 | 做法 |
|---|---|---|
| **⓪ 检索** | **1 次搜索** | **B 型必做；A/D 型只有"不知道一手源"时才做**。模板按 `--goal` 只出那一类 |
| **① 官方名录** | **0 请求** | 读 `tools/geo/gov_platforms.json`（按 goal 过滤 kind）；或抓主管部门名单页 |
| ② 页脚/友链 | 0~2 请求 | 已知站首页 → 外链域名按出现次数排序 |
| ③ 域名语法 + DNS | **0 HTTP** | `{city}rc.com` / `wz{abbr}rc.com` 生成候选批量解析；**先用已知答案验召回** |
| ④ 平台指纹 | 0~1 请求/站 | 第三方资源域名、robots MD5、favicon 字节 |
| ⑤ 明文接口 | 1~2 请求 | 页面 `script` 的 `url`+`queryData`、XHR/performance entries |

### 两条长期规则（写死，不许再犯）

```
规则一  没有候选源、或不知道一手源时，第一动作才是「检索」；已经知道官方站/API 就别检索（A/D 型）。
        不是"永远先检索" —— 天气任务去搜"XX天气网"纯属浪费。
规则二  找某类官方源，先找「主管部门的名单页」，再谈逐家搜。
        例：省级公共就业平台 -> http://job.mohrss.gov.cn/jy/index.jhtml
            1 个请求拿到 **32 条省级直链（31 省 + 兵团）**，比搜 31 次划算且权威。
```

**为什么这两条是用血换的（2026-11-14）**：

```
v13 靠 244 个域名猜，最后只有 A 级 16 个往下走，B 级 98 个全丢。
漏掉了 zjhr.com / zjrc.com（浙江省人社厅两个平台）。
   - zjrc.com 其实被枚举出来了，但 "zj" 被当成"镇江"，判 B 级，扔了
   - zjhr.com 根本没有对应模板（没有 {省}hr 这一种），永远生成不出来
一次检索：找到 5 个江苏官方平台，v13 一个都没有。
```

**推论**：凡是"猜域名能解决"的都不是真问题；**猜不出来的那一类，才是发现阶段真正的洞。**

```
招聘：省/市公共就业服务平台、人社局、人才服务中心
法规：政府公报、部委规章库、地方人大
价格：统计局、行业协会、交易所
```

### 名录从哪来：先找名单页，别逐省搜（2026-11-15 实测）

```
http://job.mohrss.gov.cn/jy/index.jhtml   《各省公共就业服务平台》
  1 个请求 -> 32 条省级平台直链（31 省 + 兵团），含 zjhr.com / js365job.com
  坑：该页用 <a><img></a> 做锚，可见文字只有「各省公共就业服务平台 版权所有」124 字
      -> 必须从 href 抽；按文字抽只能捞到 2 条（还以为是残缺数据）
名单会过期：第 6 位是 IP 直链 111.41.62.147:13332，2026-11-15 实测 ConnectionReset
-> 名单只保证「曾经存在」，抓完每条都要 1 请求验
```

### 名录必须允许「没有统一平台」（字段 coverage）

```
coverage: unified     该省有省级统一入口（人社部名单能直接拿到）
          fragmented  多线并存、没有单一入口（江苏：js365job + 省人才服务云）
          unknown     未查明（黑龙江 4 个候选全失败、河南超时）
规则：宁写 fragmented/unknown，不硬凑域名 —— 凑一个假的会污染后面所有判断
```

### 检索结果不许直接信

```
搜到 ≠ 能用。搜索结果里混着：跨省的站、第三方聚合站、高校公告页。
规则：检索只产出"候选"，必须 1 请求验（title / 岗位链接 / robots）才算数。
```

## 五、判据 F-01 … F-22（照抄第十八章）

**可达性**：F-01 robots 可读（403/5xx=拒绝）｜F-02 robots 决策（分组+最长匹配+行号）｜F-07 WAF 特征（home 与 robots 同 MD5 / `aliyun_waf_*` / 200 但正文<300 字）
**内容**：F-03 正文<300 字=空壳｜F-04 领域词命中≥2｜F-05 每页<3 条=异常｜F-06 count 只作参考｜F-21 地理重叠<5%→降级
**形态**：F-08 列表形态（SSR/SPA/接口）｜F-09 接口线索（`url`+`queryData` / `.json` / `ajax` / `fetch(`）
**平台皮肤**：F-10 平台指纹（第三方资源域名≥20）｜F-11 同部署（robots 字节相同）｜F-12 同图标（favicon 相同）｜F-13 皮肤代（静态路径数+favicon：A 代≥120 路径可批量，B 代单独适配）
**结构同库**：F-14 类目/地区识别用**锚文本**不是域名拼音｜F-15 域名召回｜F-16 IP 只解析 **www**（apex 多停放、IP 会轮转）｜F-17 同库三级（L1 指纹/L2 结构/L3 数据 n=10）
**工程**：F-18 **不信 count**，翻到 0 条或重复才停（实测 count 131 vs 实际 141）｜F-19 编码（政府/行业站常见 GBK）｜F-20 预算（任务≤200，发现≤30，渲染单列）
**发现**：**F-22 检索优先**（没有候选源时先跑 3~5 条检索模板，再进域名生成；找官方平台先找主管部门名单页）。检索条数 0 且无说明 = 漏项，要写进候选表
**名录**：**coverage 三态**（unified / fragmented / unknown）—— 不是每个省都有统一平台，不许硬凑域名

## 六、形态三态与优先级

```
SSR（列表页正文完整）→ 直接抓
接口（url+queryData / XHR JSON）→ 直接调，跳过渲染
SPA（空壳）→ ①先找接口 ②没有才渲染（v14 T2，成本≈10~20 倍）
优先级永远是 SSR > 接口 > 渲染。渲染是最后手段。
```

## 七、平台 ≠ 皮肤（决定能否批量）

```
平台（F-10）：谁家的 → 能否复用适配器
皮肤（F-13）：哪代模板 → 复用后要不要改解析
实测：同平台 7 站 robots 全同，但 A/B 两代皮肤 Jaccard 0.05 vs 0.78
→ 混成一个"同模板"会在 B 代站上全线解析失败。
```

## 八、Rule 0 不碰清单（命中即停，不升级手段，报给用户）

```
· robots 禁止该路径
· 验证码 / 人机验证
· 商业 WAF 挑战页（aliyun_waf_* / 所有路径同一页 / 200 但正文<300 字）
· 需登录才可见的非公开数据（除非用户明确授权本人账号）
· 加密签名接口（AES/HMAC 类参数，如 jrzp /zpapi/api）
· 简历/求职者栏目（Persons/、Person.asp?PerId=、resume 类）—— 一律不抓不看
```

已确认命中（2026-11-14）：华测 cti-cert、谱尼 ponytest、浙江市监局 zjamr（WAF）；hzrc.com、nbrc.com.cn、jrzp 全系（SPA/签名）。

## 十一、纪律

```
· 每任务 ≤200 请求；发现阶段 ≤30；渲染另设上限
· 每次探测都落盘到 data\raw\fixtures\（没有落盘 = 结论不可复核）
· 结论三态：✅ 真实站验过 / ⚠️ 仅假站或工具级 / ❌ 未支持
· 台账写样本量（"同库"必须有 n 和日期）
· 不为"看起来验过了"改判据
```

## 十二、常见坑（都是踩过的）

```
1 count 不可信：131 vs 实际 141 → 翻到空页/重复才停
2 apex 是停放页：省级站 apex 全 203.107.45.167，只认 www
3 IP 会轮转：同批域名隔几小时解析完全不同 → IP 只作辅助
4 GBK：政府/行业站按 UTF-8 读会乱码（njrcw、foodmate 都是）
5 分页参数名各异：jpaas=paramJson.pageNo、hotjob=page、北森=PageIndex、74cms=page
6 北森 DisplayFields：LocNames 必须与 LocId 成对，否则地点永远空
7 一个页面可能有 7 个 unitbuild 标签 → 取"像列表"的那个（含 list/列表）
8 站点模块 parse_total_pages 必须是两参（引擎按 (html, page_url) 调用）
9 两行表头会把数据行吞进表头 → 只在"表头有空位且下行≥2 关键词"时合并
10 全国大厂岗位跟着总部/工厂走：双汇+蒙牛 274 条里浙江+江苏仅 6 条 → 本地岗位找本地公司
11 缩写歧义会杀候选：zj = 浙江 or 镇江。歧义时标 ambiguous 全保留，别单选
12 B 级候选不许全丢：98 个 B 级里躺着 zjrc.com → B 级≠没价值，只等于"没验证"
13 jrzp 列表页是**三道锁**，不是一道：①headless 的 UA 被 CDN ACL 拦（403 denied by UA ACL = blacklist）
   ②disable-devtool 独立 chunk（detectors:"all" → about:blank，页面只剩 39 字节）
   ③**翻页要登录**（第 1 页免费，第 2 页起弹登录框）→ **有账号就能过（v15）**，无账号仅第 1 页；
   前两道可过（有头 + 拦 chunk），
   **第三道过不去** → 别在列表页上耗，走"首页 + 详情页" SSR
14 名单页会用图片当锚文本：人社部那份页可见文字只有 124 字，按文字抽只捞到 2 条，
   从 href 抽才是 32 条 → 抽不到时先看是不是 <a><img></a>
15 名单会过期：人社部名单第 6 位 IP 直链已 ConnectionReset；黑龙江 4 个候选全部失败
   → 拿到名单必须逐条 1 请求验，别直接写进生产
16 discover.py 的域名拼接必须是 concat（{pinyin}+"rc.com"），不是 dot（{pinyin}+".rc.com"）；
   dot 写法永远生成不出真站（hangzhou.rc.com 不存在）。省级模板还要 {abbr}hr.com 这一档，
   否则 zjhr.com 这一整类从第一步就出不来
17 拦 disable-devtool 会在对方 CDN 日志里留一条"该资源加载失败"——这是绕过痕迹，别当隐身；
   要更隐蔽得改成"让 chunk 正常加载、提前 stub 检测函数"
18 "只给你看第一页"是常见设计：翻页才要登录（jrzp 实测）。此时价值不在翻页，
   在"换关键词 × 第 1 页 + 多站首页"的组合额度
19 同一站可能同时有 SSR 面和 SPA 面（jrzp：首页/详情 SSR，列表 SPA）→ 先找 SSR 面，
   往往压根不用碰检测
```
